# Make Kitchen the canonical owner of Analysis ingestion

Kitchen is the sole runtime owner of canonical Pantry state after Analysis. Pantry owns one Analysis ingestion operation that reconciles completed evidence into a candidate graph, while Counter fetches the committed Pantry and does not prune or re-import Analysis results locally. Successful workflow Analysis replaces Analysis-derived Vulnerability assets only for repositories listed as successfully analyzed. Failed and unconfirmed repositories, runtime evidence, Recon, Loot, Agents, and other engagement-derived state remain untouched. Successful deep Analysis separately replaces secret-detection-derived Secret assets only for repositories whose secret detection completed; normal Analysis and failed or skipped secret detection preserve existing Secret assets. Workflow and Job assets remain upsert-only because runtime evidence may depend on them. Partial organization Analysis reconciles all explicitly successful repository scopes in one operation without treating the requested organization as authoritative.

All Analysis-derived Assets use `DiscoveredBy = "analysis"`. Secret-detection evidence uses an engine-neutral classification such as `analysis_evidence = "secret_detection"`; the repository platform remains the Asset provider, and a detector name may be retained only as diagnostic metadata. Reconciliation never depends on a detector name, so replacing Gitleaks does not change Pantry semantics. Legacy GitHub Vulnerability assets without `DiscoveredBy` may be treated as Analysis-derived because Kitchen has no other production source for them.

An Analysis result remains valid when Pantry reconciliation fails. The Counter-Kitchen contract reports only whether graph reconciliation committed or failed, without server mutation counts. Counter retains its last committed Pantry and shows a sanitized reconciliation failure. There is no automatic background retry because a queued stale Analysis result could overwrite newer engagement evidence; rerunning Analysis is the explicit retry path.

This replaces the duplicate Kitchen and Counter importers and the unused legacy Pantry importer. A generic multi-source provenance framework is deferred until a second ingestion source demonstrates the need for it. Implementation of this decision is intentionally deferred.
