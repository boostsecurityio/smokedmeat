# Persist Pantry reconciliation before live publication

Analysis ingestion builds and validates a complete candidate Pantry while the committed Pantry remains readable. A Pantry-level writer gate covers every mutator, so ordinary writers wait during reconciliation while readers continue to observe the prior committed state. The candidate is serialized once, validated, and persisted before a short, non-failing replacement of the live Pantry internals. The Pantry pointer remains stable for GraphHub and other consumers. Observer publication occurs only after the live replacement, and bulk Analysis ingestion emits one revisioned committed-state signal that causes graph clients to refresh from a snapshot. Ordinary Pantry mutations retain granular observer events.

Kitchen continues to store Pantry as one JSON value in one BBolt transaction. This matches BBolt's single-writer, multiple-reader, ACID transaction model and keeps the database write short because candidate construction and serialization happen before the transaction. A serialization or persistence error leaves the previous graph in both the database and live Pantry. A process failure after durable persistence but before live replacement stops the process; restart loads the durable candidate. No fallible work occurs between successful persistence and live replacement. The existing load path must copy BBolt values inside the read transaction before decoding because BBolt byte slices are transaction-scoped.

The whole-snapshot layout is accepted for the current scale, with an explicit large-organization risk. Each Analysis rewrites the complete serialized Pantry, briefly occupies BBolt's single writer, and may increase the database file's high-water size because freed pages are reusable but the file does not automatically shrink. Implementation must record candidate construction, serialization, persistence, and publication timings together with Asset, Relationship, and serialized-byte counts, and must include a synthetic large-graph performance test. No arbitrary graph-size rejection is introduced until operational evidence justifies one. Persistence remains behind the Analysis ingestor's adapter so a later record-oriented store does not change reconciliation semantics.

When implemented, the optional engine-neutral Analysis evidence property advances the Kitchen schema minor from 2.5 to 2.6 under [ADR-0001](0001-separate-kitchen-schema-version-from-application-releases.md). Required verification includes persistence-failure rollback, reopen-after-commit, old-or-new reader visibility, race detection, and large-graph performance behavior. Implementation of this decision is intentionally deferred.
